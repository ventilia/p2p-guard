# P2P Guard — план реализации

Браузерное расширение для Binance P2P: досье на контрагента, чёрный список,
отзывы, командная работа + Node.js-бэкенд с общей базой + админ-панель.
Аналог BybitEye/TradeCode, только под Binance.

---

## 1. Архитектура

```
┌──────────────────────── Браузер пользователя ────────────────────────┐
│                                                                      │
│  page-world (hook.js)          content script            popup       │
│  ┌────────────────────┐      ┌──────────────────┐    ┌────────────┐  │
│  │ обёртка WebSocket  │─msg─▶│ Shadow DOM UI    │    │ логин,     │  │
│  │ + fetch (чат P2P)  │      │ (React, досье)   │    │ настройки  │  │
│  └────────────────────┘      └────────┬─────────┘    └─────┬──────┘  │
│                                       │ chrome.runtime      │        │
│                              ┌────────▼─────────────────────▼─────┐  │
│                              │  background (service worker)       │  │
│                              │  • детект ордера по URL            │  │
│                              │  • Binance private API под cookie  │  │
│                              │    пользователя (наружу не уходит) │  │
│                              │  • нормализация → наш backend      │  │
│                              │  • access/refresh, очередь синка   │  │
│                              └────────────────┬───────────────────┘  │
└───────────────────────────────────────────────┼──────────────────────┘
                            только бизнес-данные │ HTTPS + JWT
                                                 ▼
                     ┌────────────────────────────────────────┐
                     │  Backend: Node.js + Fastify + Prisma   │
                     │  PostgreSQL (общая база ЧС/отзывов)    │
                     └──────────────────┬─────────────────────┘
                                        ▲
                     ┌──────────────────┴─────────────────────┐
                     │  Admin SPA (React + Vite)              │
                     │  токены, команды, блокировки, статы    │
                     └────────────────────────────────────────┘
```

**Стек**

| Слой | Технологии | Почему так |
|---|---|---|
| Расширение | Manifest V3, TypeScript, React 18, esbuild | esbuild вместо Vite/crxjs — детерминированная сборка IIFE-бандла для content script без бета-плагинов |
| Backend | Node 20+, Fastify 5, Prisma, PostgreSQL, zod, JWT | Fastify быстрый и с нормальными хуками; Prisma даёт типы и миграции |
| Admin | React 18 + Vite | обычная SPA, ходит в тот же API под ролью ADMIN |
| Инфра | Docker Compose (Postgres) | локальный запуск в одну команду |

**Почему cookie биржи не уходит на сервер.** Все приватные вызовы Binance идут
из service worker самого пользователя (`credentials: "include"` + `host_permissions`).
Наружу отдаём только нормализованные бизнес-данные: UID/ник контрагента, суммы,
статусы ордеров. Это не «паранойя», а условие работоспособности: серверные
запросы с чужой сессией Binance ловит антифрод и банит аккаунты пользователей.

## 2. Модель данных (PostgreSQL)

- `User` — UID биржи, роль, статус, команда, подписка.
- `Team` + `TeamNote` — команда и её приватные заметки по контрагентам.
- `InviteToken` — токены доступа: хэш токена, лимит использований, срок, роль, команда.
- `RefreshToken` — сессии устройств, ротация и отзыв.
- `Counterparty` — контрагент биржи (`exchange + externalId` уникальны) + снимок биржевой статистики.
- `Review` — отзыв: POSITIVE / NEUTRAL / NEGATIVE + текст. Один отзыв на пару (автор, контрагент), повтор — правка.
- `BlacklistEntry` — запись ЧС: `GLOBAL` (общая база) или `TEAM` (только своя команда).
- `Requisite` + `CounterpartyRequisite` — карты/телефоны контрагента и когда их видели.
- `Order` — сделки пользователей (объём, статус, контрагент) — источник статистики для админки.
- `MessageTemplate` — шаблоны быстрых ответов в чат.
- `AuditLog` — кто, что и над кем сделал.

## 3. API (`/v1`)

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| POST | `/auth/activate` | по токену | активация: токен + Binance UID + пароль → аккаунт |
| POST | `/auth/login` | — | UID + пароль → access/refresh |
| POST | `/auth/refresh` `/auth/logout` | — | ротация / выход |
| GET | `/me` | user | профиль, команда, подписка |
| POST | `/counterparties/lookup` | user | **главный вызов**: upsert контрагента + всё досье + риск-скор |
| GET | `/counterparties/:id/dossier` | user | то же без записи |
| POST/DELETE | `/reviews`, `/reviews/:id` | user | отзыв (upsert) / удалить свой |
| PUT/DELETE | `/teams/notes` | team | заметка команды по контрагенту |
| GET/POST | `/teams/me`, `/teams/me/invites` | lead | состав команды, инвайты |
| POST/DELETE | `/blacklist`, `/blacklist/:id` | user/lead | добавить/снять запись ЧС |
| POST | `/orders/sync` | user | пакетная выгрузка ордеров |
| POST | `/requisites/observe` | user | реквизиты, замеченные в чате |
| CRUD | `/templates` | user | шаблоны ответов |
| CRUD | `/admin/*` | admin | токены, команды, блокировки, статистика, подписки, аудит |

## 4. Риск-скор

Аддитивная прозрачная модель — всегда возвращает список факторов, чтобы трейдер
видел, почему «красный», а не верил чёрному ящику:

| Фактор | Вклад |
|---|---|
| В глобальном ЧС | +70 |
| В ЧС своей команды | +55 |
| Реквизит совпал с реквизитом из ЧС | +45 |
| Негативные отзывы (доля × количество) | до +35 |
| Высокая доля отмен по нашей базе | до +20 |
| Молодой аккаунт биржи (< 30 дней) | +15 |
| Мало сделок при большом среднем чеке | +12 |
| Долгое среднее время перевода | +8 |
| Позитивные отзывы | −20 |
| Много успешных сделок с командой | −15 |

Итог 0…100 → `LOW / MEDIUM / HIGH / CRITICAL`.

## 5. Безопасность (базовый разумный минимум)

- JWT: access 15 мин, refresh 30 дней с ротацией; пароли — `scrypt` из stdlib
  (никаких нативных модулей, ничего не ломается при сборке на Windows).
- Привязка учётки к Binance UID: каждый запрос несёт `X-Binance-Uid`,
  несовпадение → `409 UID_MISMATCH` (одна учётка = один аккаунт биржи).
- RBAC `USER / TEAM_LEAD / ADMIN` + изоляция команд на уровне сервисов.
- helmet, CORS-allowlist (`chrome-extension://<id>` + домен админки),
  rate-limit (общий + жёсткий на `/auth/*`), валидация всех входов через zod,
  единый формат ошибок, аудит-лог админских действий.
- Чего сознательно не делаем: «отрисовка» чеков и любые инструменты подделки
  документов. Продукт — аналитика и ЧС.

## 6. Этапы

1. **MVP (этот код):** бэкенд + БД + расширение с досье + отзывы/ЧС/заметки/команды + админка. Всё бесплатно, поля подписки заложены.
2. **HAR-верификация Binance API.** Все эндпоинты приватного C2C API вынесены в
   один адаптер `extension/src/background/binance.ts` — после снятия HAR с живой
   страницы ордера правится только он, остальной код не трогается.
3. **Чат:** парсинг реквизитов из WS-канала, предупреждение при смене реквизита
   в процессе сделки.
4. **Импорт покупных баз мошенников** — отдельный `source` у записи ЧС с весом доверия.
5. **Биллинг**, публикация в Chrome Web Store, вторая биржа как ещё один адаптер.
