# P2P Guard

Браузерное расширение для трейдеров **Binance P2P**: при открытии ордера поверх
страницы появляется досье на контрагента — чёрный список, отзывы, статистика
сделок, реквизиты и риск-скор. Плюс командная работа и админ-панель.

Аналог BybitEye/TradeCode, только под Binance и со своим бэкендом.

```
p2p-guard/
├── backend/     Node.js + Fastify + Prisma + PostgreSQL — API и общая база
├── extension/   Chrome MV3 + React — панель в ордере и попап
├── admin/       React + Vite — админ-панель
├── PLAN.md      архитектура, модель данных, риск-скор, этапы
└── docker-compose.yml
```

## Быстрый старт

### 1. База

```bash
docker compose up -d
```

Postgres поднимется на **localhost:5433** (порт нестандартный, чтобы не
конфликтовать с локально установленным Postgres).

### 2. Бэкенд

```bash
cd backend
cp .env.example .env
npm install
npm run db:push      # создать таблицы
npm run seed         # админ + демо-команда + токен доступа
npm run dev          # http://localhost:4000/v1
```

`npm run seed` печатает в консоль логин администратора и **токен доступа** —
сохраните его, он понадобится для активации расширения.

По умолчанию: UID `100000001`, пароль `admin12345` (меняется в `.env`).

### 3. Админ-панель

```bash
cd admin
npm install
npm run dev          # http://localhost:5174
```

Вход — UID и пароль администратора.

### 4. Расширение

```bash
cd extension
npm install
npm run build        # или npm run watch для разработки
```

Затем: `chrome://extensions` → включить «Режим разработчика» →
**«Загрузить распакованное»** → выбрать папку `extension/dist`.

Открыть попап расширения → вкладка **«Активация»** → вставить токен из seed,
придумать пароль → готово. UID Binance подставится сам, если вы залогинены на
binance.com в этом браузере.

## Как это работает

1. Пользователь открывает страницу ордера на `p2p.binance.com`.
2. Service worker расширения ловит `orderNo` из URL и запрашивает у **приватного
   API Binance** детали ордера и профиль контрагента — под cookie самого
   пользователя, внутри его браузера. Сессия биржи никуда не пересылается.
3. Нормализованные данные (UID/ник контрагента, сумма, статус) уходят на наш
   бэкенд в `POST /v1/counterparties/lookup`.
4. Бэкенд собирает досье: чёрный список (общий + командный), отзывы всех
   пользователей, заметку команды, статистику сделок по нашей базе, реквизиты,
   и считает риск-скор.
5. Content script рисует карточку в Shadow DOM поверх страницы.

Из чата ордера (перехват WebSocket в page-world) вытягиваются карты и телефоны
и привязываются к контрагенту — так ловится смена реквизитов и совпадение
реквизита с уже известным мошенником.

## Возможности

**Расширение**
- Досье контрагента прямо в ордере: ник, UID, страна, статус в ЧС.
- Риск-скор 0…100 с расшифровкой факторов (почему именно такой балл).
- Отзывы: свои, командные и всех пользователей базы; автор маскируется.
- Заметка команды по контрагенту.
- Статистика Binance (процент завершённых, возраст аккаунта, среднее время).
- Ордера по нашей базе: рынок / команда / вы.
- Реквизиты, замеченные в чате, с пометкой «в ЧС».
- Быстрые ответы (шаблоны) в один клик.
- Панель перетаскивается и сворачивается в кнопку с цветовым индикатором риска.

**Команды**
- Общая база отзывов, ЧС и заметок внутри команды.
- Тимлид выдаёт токены на вступление и исключает участников.
- Статистика по каждому участнику: объём, успешные и отменённые сделки.

**Админ-панель**
- Сводка: пользователи, обороты, контрагенты, отзывы, ЧС.
- Пользователи: поиск, блокировка с причиной, роль, команда, сброс пароля.
- Карточка пользователя: объём торгов, успешные/отменённые сделки и **с кем
  именно** он торговал (топ контрагентов с пометкой ЧС).
- Токены доступа: выдача, лимит использований, срок, отзыв.
- Команды: создание, назначение тимлида, удаление.
- Подписки: продление, смена плана, отмена (сейчас все на FREE, ограничения
  не применяются).
- Аудит всех административных действий.

## Безопасность

- Cookie-сессия Binance **не покидает браузер** — иначе антифрод биржи банит
  аккаунты пользователей.
- JWT: access 15 минут, refresh 30 дней с ротацией и детектом переиспользования
  (повторное предъявление отозванного токена гасит всю цепочку).
- Пароли — `scrypt` из стандартной библиотеки Node, без нативных модулей.
- Учётка жёстко привязана к UID Binance (`X-Binance-Uid`, при несовпадении 409).
- Роли `USER / TEAM_LEAD / ADMIN`, изоляция командных данных на уровне сервисов.
- helmet, CORS-allowlist, rate-limit (жёсткий на `/auth/*`), zod-валидация
  всех входов, единый формат ошибок, аудит-лог.
- Токены доступа хранятся в базе только хэшем — сырое значение показывается
  один раз при выпуске.

## Приватный API Binance

Пути и структуры полей приватного C2C API не документированы. Весь контакт с
биржей собран в одном файле — **`extension/src/background/binance.ts`**.
После снятия HAR с живой страницы ордера правится только он:

1. Открыть реальный ордер на `p2p.binance.com`;
2. DevTools → Network → фильтр `bapi`;
3. Сверить `ENDPOINTS`, `ORDER_STATUS_MAP` и нормализаторы
   `normalizeOrderDetail` / `normalizeUserDetail`.

Остальной код расширения при этом не меняется.
