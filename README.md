# P2P Guard

Досье контрагента для Binance P2P: чёрный список, отзывы, статистика сделок и
риск-скор прямо на странице ордера. Плюс общая база для команды и админ-панель.

Три части:

| Папка | Что это |
|---|---|
| `extension` | расширение Chrome (MV3): панель в ордере и попап |
| `backend` | API на Fastify + PostgreSQL через Prisma |
| `admin` | админ-панель на React + Vite |

## Что нужно поставить

- **Docker Desktop** — под базу
- **Node.js 20+**

## Запуск

Все три команды из корня проекта, каждая в своём терминале.

**1. База**

```bash
docker compose up -d
```

**2. Сервер**

```bash
cd backend && npm install && npm run db:deploy && npm run seed && npm run dev
```

`db:deploy` накатывает миграции, `seed` создаёт админа и печатает токен активации.
Дальше достаточно `npm run dev`.

**3. Админка**

```bash
cd admin && npm install && npm run dev
```

Откроется на `http://127.0.0.1:5174`. Вход: UID `100000001`, пароль `admin12345`.

**4. Расширение**

```bash
cd extension && npm install && npm run build
```

Затем `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» →
выбрать `extension/dist`.

## Проверка, что всё живо

```bash
curl http://localhost:4000/health
```

Ответ `{"ok":true,"db":true,...}` означает, что сервер видит базу. Если база
недоступна, ответ будет `503` и `"db":false` — проверка ходит в неё запросом,
а не просто отвечает «жив».

Админка — `http://127.0.0.1:5174`, стенд интерфейса — см. ниже.

## Данные для проверки

Токен активации печатает `npm run seed`. Ещё один можно выпустить из админки:
раздел «Токены» → «Создать».

Активация в расширении: значок P2P Guard → «Активация» → вставить токен →
задать пароль от 8 символов. Повторный вход — через «Вход».

## Стенд интерфейса

Собирает все экраны в один HTML без базы и сети — удобно показывать:

```bash
cd extension && npm run preview
```

Файл `extension/preview/dist/index.html` открывается двойным кликом. Жёлтая
кнопка «Открыть демо-ордер Binance» показывает панель на макете страницы ордера.

## Как это работает

**Панель в ордере** встраивается обычным блоком в колонку ордера и
прокручивается вместе со страницей. В полосу чата не заходит: столбец переписки
у Binance прибит к окну, и блок в его полосе пересекался бы с ним при каждой
прокрутке.

**Данные о контрагенте** берутся из трёх источников по убыванию надёжности:
перехват ответов страницы, разбор вёрстки ордера и страница профиля
контрагента. Профиль расширение открывает фоновой вкладкой и сразу закрывает —
пользователь остаётся в ордере.

Прямые запросы к приватному C2C API биржа отбивает антифродом, поэтому на них
продукт не опирается.

**Риск-скор** складывается из чёрного списка, категорий жалоб, отзывов,
статистики биржи и истории сделок. Панель всегда показывает, из чего он
получился.

## Боевой деплой

Локальный запуск выше — для разработки и показа. Для сервера в интернете:

```bash
cd backend && npm run build && npm start
```

`npm start` сам накатывает миграции. Конфиг для Railway лежит в
`backend/railway.json`, подойдёт и Render, и обычный VPS.

Переменные окружения сервера:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | адрес PostgreSQL |
| `JWT_SECRET` | случайная строка от 16 символов |
| `NODE_ENV` | `production` |
| `SEED_ADMIN_PASSWORD` | свой пароль, `admin12345` в бой не годится |
| `CORS_ORIGINS` | адрес админки |
| `ALLOW_ANY_EXTENSION_ORIGIN` | `false`, когда у расширения появится постоянный ID |

Расширение под боевой адрес собирается так:

```bash
PG_API_URL=https://ваш-домен/v1 npm run build:prod --prefix extension
```

Адрес попадает и в настройки, и в `host_permissions` манифеста — без второго
service worker получит отказ ещё до запроса.

Админка — статика: `cd admin && npm run build`, папку `dist` можно положить
куда угодно.
